## 定位证据

1. 实验四与实验五 50% 组的 1753 张训练图、标签和模糊强度分配一致；对应验证、测试变换数据的哈希一致。实验五生成数据实际文件共检查 10391 组图片/标签，与清单一致。
2. 初始预训练权重相同。对应训练参数除输出、数据目录和任务名称外一致；评估记录指向对应权重，重新汇总原始指标也能得到原报告。
3. 对同一数据、seed=42 连续初始化两次训练器：初始模型权重、样本顺序、NumPy 和 PyTorch 随机状态一致；Python 随机状态不同，前 3 批增强图片及边框的哈希不同。
4. 跟踪随机数调用，发现 Ultralytics 8.4.147 的 `utils/events.py` 在首次导入时创建 `Events()`；其 `session_id` 调用 `random.random()`。导入发生在训练器已经设置种子之后。同一进程第二次训练时模块已缓存，不再消耗这一次随机数。事件是否启用不改变初始化时这一调用。
5. 仅在第二次初始化补上该随机数调用（仅诊断，不用于生产修复），前 3 批增强图片和边框、模型及随机状态全部恢复一致。

## 原因与修复

实验四每个新模型通过独立子进程训练。实验五六个模型在同一个 Python 进程依次训练，只有第一个模型经历首次模块初始化；因此设置相同 seed 并未得到相同随机增强序列。这会改变从第一轮开始的训练轨迹，破坏了跨实验和组间预期的配对。

新增 `scripts/isolated_training.py`，每个模型使用当前解释器启动独立进程；初始权重和实际参数通过 JSON 传入，保留实时输出、日志和子进程失败传播。没有在生产代码补随机数，也没有修改第三方安装包。

实验五、尺寸对照和 Mosaic 的新训练统一采用该入口，避免同类问题。实验四已有独立进程设计。对历史其他实验是否受影响需结合实际运行/恢复顺序判断，不能仅凭脚本中有循环就断言其成绩错误。
